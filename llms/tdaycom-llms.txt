# tday

> tday (tday.com) is a Y Combinator-backed (Spring 2026) AI platform, operated by Altacomm Technologies Pty. Ltd. of Adelaide, South Australia, that turns what a software team ships into on-brand creative. It connects to a GitHub repository or drives a live site through the browser like a user, and on every release produces a launch package — an end-to-end demo video recorded from real product flows, a promotional feature showcase, and on-brand social graphics — then publishes that creative to social channels and measures it. A second surface generates brand-aware still designs from a text prompt against a stored brand. Both are reachable from an AI assistant through tday's Model Context Protocol server.

This llms.txt was generated by the API Evangelist enrichment pipeline from tday's public surface and the artifacts in this repository. tday publishes no official /llms.txt (https://tday.com/llms.txt returns 404, checked 2026-08-13).

## MCP

tday ships BOTH a hosted remote MCP endpoint and a local stdio MCP server. They front the same nine tools.

- [tday MCP server (hosted)](https://tday.com/api/mcp): Remote streamable-HTTP endpoint. Add it as a Claude custom connector. OAuth 2.1 secured (authorization_code + PKCE S256, dynamic client registration, single scope `tday`). Returns 401 with an RFC 9728 WWW-Authenticate challenge to unauthenticated requests.
- [Local MCP server](https://www.npmjs.com/package/@designtday/mcp): `npx -y @designtday/mcp install` — runs on your machine over stdio, links to your tday account through a loopback browser flow, and auto-configures Claude Code, Cursor and Gemini CLI.
- [MCP setup page](https://tday.com/mcp): tday's own install instructions for both paths.
- [OAuth Authorization Server metadata](https://tday.com/.well-known/oauth-authorization-server): RFC 8414 discovery document.
- [OAuth Protected Resource metadata](https://tday.com/.well-known/oauth-protected-resource): RFC 9728 discovery document (resource = https://tday.com/api/mcp).

### Tools

- `tday_whoami` — account identity, plan, API credit balance, billing-period usage.
- `tday_list_brands` — list brands as lightweight summaries (limit 1-100, default 50; offset).
- `tday_get_brand` — one brand with its colors, logos, fonts, images and knowledge base.
- `tday_create_brand` — create a brand from a website URL; colors, fonts and logos are auto-extracted.
- `tday_list_designs` — list designs as lightweight summaries (limit/offset).
- `tday_get_design` — one design including its generations.
- `tday_generate_design` — generate a design from a prompt against a brandId. Asynchronous.
- `tday_poll_generation` — poll a generation to `completed` or `failed`. Typically 30-90 seconds.
- `tday_download_image` — save a completed image locally (HTTPS host allowlist, 50MB cap, writes inside cwd only).

## Agent skills

tday publishes its own agent instructions as Claude Code slash commands, installed by `npx -y @designtday/mcp install`: `/tday`, `/tday-design`, `/tday-brand`, `/tday-credits`, `/tday-ideas`. They are captured verbatim in this repository under `skills/`.

## Calling conventions

- Auth: `authorization: Bearer <token>`. No API-key page and no key prefix; tokens come from the browser link flow.
- Pagination: `limit` (1-100, default 50) + `offset` (default 0), server-side, with a `pagination` object in the response.
- Errors: bare vendor JSON `{"error": "..."}` — not RFC 9457. 400/401/403/404/429/5xx.
- Rate limits: a 429 covers both an exhausted API credit balance and an exhausted rate-limit window, with nothing in the response to distinguish them. No `Retry-After` and no `RateLimit-*` headers are published.
- Idempotency: none. tday's own MCP annotations declare `tday_generate_design` and `tday_create_brand` as `idempotentHint: false` — a retried generate bills again.
- Long-running work: submit then poll. No webhooks or callbacks.
